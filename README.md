## Repository rules

1. **One canonical folder/file per problem.** Use the LeetCode problem number and slug, e.g. `0001-two-sum/solution.cpp`. Topic indexes link to this file; they do not copy it.
2. **No duplicate folders for re-submissions.** Re-submitting a previously solved problem for practice must update the existing canonical solution, not create another problem entry.
3. **Better solution later?** Add a clearly labelled `Optimal approach` / `Approach 2` section or a separate named file inside the same problem folder. Keep the earlier approach if it is useful; do not duplicate the problem itself.
4. **Track verified history only.** A checkbox is marked complete only when the problem is identified and its existing solution/history is verified. Do not invent titles or code.
5. **Historical backlog pace:** target one previously solved problem per day, oldest/pending-first where reliable submission dates are available.
6. **New accepted submissions:** use the linked LeetHub extension workflow in [docs/AUTOMATION.md](docs/AUTOMATION.md). A browser extension needs to be installed and authorized in the user's browser; GitHub alone cannot read private/session-only LeetCode submission code.
